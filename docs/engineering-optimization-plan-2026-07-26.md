# 工程化优化实施计划与性能基线

> 建立时间：2026-07-26
> 适用范围：当前本地开发链路、Next.js 控制台、Node.js 开发 API、Python 来源桥接，以及后续 Rust 生产服务。
> 核心约束：不改变现有入口、请求参数、业务流程和返回结构；优先做可验证的小步重构，不进行一次性推倒重写。

## 1. 本轮目标

本轮工作把“能够运行”提升为“能够持续验证和安全演进”，重点覆盖：

1. 建立前端单元测试和浏览器端到端回归，避免布局、导航和状态渲染再次退化。
2. 建立可重复执行的性能基线，后续优化必须用数据对比，不凭主观感受。
3. 逐步统一前端请求缓存、加载状态和错误处理，减少组件内部重复请求。
4. 加强封面与页面图片的完整性校验、重试和可观测性。
5. 保持开发 API 与 Rust 生产边界清晰，避免把临时实现固化成最终架构。
6. 持续补齐中文文档，使启动、测试、验收和回滚均可复现。

## 2. 当前架构与边界

~~~mermaid
flowchart LR
    U[浏览器用户] --> W[Next.js 控制台]
    W --> A[统一 API 客户端]
    A --> D[Node.js 开发 API]
    A -.生产目标.-> R[Rust Axum API]
    D --> S[来源注册表]
    R --> Q[任务队列与运行时]
    S --> P[Python 来源桥接]
    Q --> P
    P --> C[封面与页面缓存]
    P --> F[本地下载文件]
    D --> L[任务与书库本地数据]
~~~

模块职责保持如下：

| 层级 | 职责 | 禁止事项 |
| --- | --- | --- |
| 页面与组件 | 展示、交互、可访问性 | 直接读取本地文件或拼接来源协议 |
| 前端数据层 | 请求去重、缓存、状态归一化 | 将服务端内部字段泄漏给组件 |
| API 组合层 | 参数校验、任务编排、兼容输出 | 在路由中堆叠来源专属解析 |
| 来源适配层 | 网站特有鉴权、搜索和页面解析 | 绕过登录、验证码、付费墙或封禁 |
| 运行时与存储 | 队列、并发、缓存、原子写入 | 无界并发、无上限日志和静默失败 |

开发态首页不能替代生产构建性能结论；它主要用于发现明显回退。后续引入请求缓存、图片完整性检查或组件拆分后，使用同一脚本与同一采样数复测。

### 5.3 性能门槛

- 单元测试和正式构建不得较基线持续恶化 20% 以上；单次异常需连续复测三次确认。
- API 健康检查 p95 目标维持在 20 ms 内。
- 开发态首页 p95 目标维持在 150 ms 内。
- 搜索和图片链路单独记录来源耗时、排队耗时、重试次数，不能只记录总耗时。
- 新缓存必须有容量上限、失效策略和命中率指标，禁止无限增长。

同一台机器、同一脚本完成复测。下表的“变化”采用 $(A-B)/B$，负值表示耗时或体积下降。

| 指标 | 优化前 | 当前 | 变化 |
| --- | ---: | ---: | ---: |
| 单元测试总耗时 | 2,642.1 ms（13 项） | 3,210.9 ms（21 项） | +21.53% |
| 单项测试平均耗时 | 203.2 ms | 152.9 ms | -24.77% |
| Next.js 正式构建 | 9,741.9 ms | 9,129.4 ms | -6.29% |
| standalone 产物 | 16,335,149 B | 16,370,915 B | +0.22% |
| static 产物 | 931,717 B | 957,835 B | +2.80% |

## 6. 搜索与图片链路优化准则

搜索链路保持原有输入和输出，仅调整内部组织：

当前前端通过单一 QueryProvider 管理只读请求。任务、来源、文件库、标签统计和远程阅读会话使用稳定查询键；同键在途请求自动合并，显式刷新会先失效对应缓存。创建搜索、继续加载、下载等写操作仍按原有 POST 语义执行，不进入读缓存。

~~~mermaid
flowchart TD
    I[规范化搜索条件] --> K[生成稳定缓存键]
    K --> H{缓存或在途请求命中}
    H -- 是 --> O[复用结果]
    H -- 否 --> V[校验来源能力]
    V --> P[有界并发搜索]
    P --> N[结果规范化与去重]
    N --> X[全局禁用词过滤]
    X --> O
~~~

图片状态机不把第一次未加载等同永久失败：

~~~mermaid
stateDiagram-v2
    [*] --> 等待加载
    等待加载 --> 已显示: 图片解码成功
    等待加载 --> 延迟重试: 超时或暂时网络错误
    延迟重试 --> 等待加载: 指数退避且未超过上限
    延迟重试 --> 永久失败: 达到上限或明确拒绝
    已显示 --> [*]
    永久失败 --> [*]
~~~

图片响应会校验 HTTP 状态、Content-Type、最小字节数以及 JPEG、PNG、GIF、WebP、AVIF 文件签名。旧缓存命中时只读取前 32 字节；签名无效会删除并在同一个 single-flight 中重新获取。健康接口以可选 thumbnail_cache 字段暴露 requests、hits、misses、shared、downloads、retries 和 in_flight 快照；图片响应同时返回 X-Thumbnail-Cache 与 nosniff。重试保持有界，避免大量封面同时重试形成请求风暴。

## 7. 兼容性、异常与隐私

1. 原有 /v1/tasks、/v1/library、/v1/reader、/v1/sources 路径不改名。
2. 现有请求字段和返回结构保持兼容；新增诊断信息只使用可选字段。
3. 空数组、缺失标签、无封面、部分来源失败和任务被取消都必须可安全渲染。
4. Cookie、请求头、下载文件、任务运行数据继续只保存在被 Git 忽略的本地目录。
5. 不记录完整认证头、私有链接查询参数或来源响应正文。
6. 发生异常时保留用户可理解的摘要，同时在本地诊断中记录受控的错误类型和重试信息。

## 8. 发布、回滚与完成定义

每个阶段采用独立小提交，必须满足：

- 单元测试通过；
- 桌面和移动端浏览器回归通过；
- scripts/check.ps1 全部通过；
- 公开仓库隐私扫描通过；
- 无意外生成文件进入提交；
- 变更文档记录设计依据、验收结果和已知限制；
- 推送后 GitHub Actions 通过。

回滚优先回退单个阶段提交。缓存和可选字段必须允许旧代码忽略，新入口在未完成纵向切片前保持“规划中”禁用状态。

# 连接状态与任务更新降级设计

> 日期：2026-07-31
> 范围：`apps/web` 前端连接状态、任务实时更新与公网隧道兼容

## 问题与根因

旧实现只维护 `eventStreamReady` 一个布尔值，并直接用它显示“实时”或“离线”。
这混淆了两种不同能力：

1. 后端 API 是否可以处理普通 `/v1/**` 请求；
2. 浏览器是否成功建立任务 SSE 实时事件流。

Cloudflare Quick Tunnel 等中间链路可能允许普通 HTTP 请求，却不稳定支持 SSE。
此时搜索、文件库和任务接口都可以使用，旧界面仍会错误显示“离线”。

## 状态模型

前端现在分别维护：

- `ApiConnectivity`：`connecting | online | offline`
- `TaskUpdateTransport`：`connecting | realtime | polling`

展示规则如下：

| API 状态 | 更新通道 | 页面状态 | 行为 |
| --- | --- | --- | --- |
| connecting | 任意 | 连接中 | 等待首次 API 请求 |
| online | realtime | 实时 | SSE 推送，活动任务每 4 秒低频校准 |
| online | polling | 在线 · 轮询 | 每 4 秒刷新任务，SSE 自动重连 |
| offline | 任意 | 离线 | 每 6 秒探测 API 恢复 |

只有任务 API 请求失败才会标记 API 离线。单独的 SSE 错误只触发轮询降级，
不会再把整个应用误判为离线。

## 代码边界

- `src/lib/connectivity-model.ts`
  - 纯状态模型；
  - 统一状态文字、样式语义与轮询间隔；
  - 不依赖 React，可单独测试。
- `src/components/dashboard.tsx`
  - 负责浏览器连接生命周期；
  - SSE 成功时切换实时模式；
  - SSE 失败时切换轮询；
  - API 成功/失败时更新真实连接状态。
- `app/globals.css`
  - 分别提供连接中、实时、轮询降级、离线的视觉状态。

该设计没有修改前端 API 封装、后端业务接口或 Python/Rust 双链路契约。

## 恢复策略

- SSE 的浏览器 `EventSource` 会继续自动重连；重连成功后恢复“实时”。
- 轮询请求使用在途锁，避免慢请求产生重叠调用。
- 组件卸载后不再提交异步结果，避免无效状态更新。
- API 离线时降低探测频率，兼顾恢复速度与资源占用。

## 验收

- 单元测试验证“API 在线 + SSE 失败”必须显示“在线 · 轮询”。
- 单元测试验证轮询、离线探测和实时空闲三类间隔策略。
- Playwright 在桌面 Chromium 与 Pixel 7 环境拦截 SSE 为 `503`，
  验证页面不显示“离线”且保留任务更新能力。
- 公网 Quick Tunnel 使用 Pixel 7 视口执行页面、宽度和 `/v1/sources` 联合检查。
## 公网前端运行方式与实测

公网入口不再直接代理 Next.js 开发服务器。`public-access.ps1` 使用
`.next-public` 独立构建生产前端，并在 `3100` 端口运行；本地开发仍使用
`.next` 与 `3000`，两套缓存和进程互不覆盖。

2026-07-31 在同一台电脑、同一条 Quick Tunnel 链路下的 Pixel 7
浏览器实测：

| 运行方式 | 客户端脚本 | 水合结果 | API 与交互 |
| --- | ---: | --- | --- |
| 3000 Next/Turbopack 开发服务器 | 约 20 个，单个最慢超过 25 秒 | 等待 60 秒仍未完成 | 未发出 `/v1` 请求，导航不可点击 |
| 3100 Next.js 生产服务器 | 优化后的生产资源 | 约 6.4 秒完成 | `/v1/sources` 返回 200、3 个源，导航正常 |

生产链路最终状态为“在线 · 轮询”，页面宽度与 Pixel 7 视口同为
`412px`，没有横向溢出。

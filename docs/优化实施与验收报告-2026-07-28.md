## 3. 关键设计依据

### 3.1 来源适配器

来源差异只存在于桥接器和注册表：公共搜索归一化、下载配额、图片校验、结果去重、错误模型、进度、持久化与 UI 消费均在公共层实现。新增来源不得复制一整条任务链路。

### 3.2 阅读器

修改前，页面组件直接创建多个临时 `Image`，切页只靠布尔变量忽略回调，浏览器请求仍可能继续。修改后，投机预加载进入 `ReaderPreloadQueue`：并发上限为 3、键去重、切页取消窗口外请求、关闭阅读器全部取消。可见页的 `<img>` 不属于投机队列，因此取消不会把当前页面清空。

修改前只有 `last_page`：

```ts
updateRemoteReaderProgress(sessionId, { last_page: page.index });
```

修改后仍保留 `last_page`，并增加可选模式进度：

```ts
{
  last_page,
  reading_mode,
  reading_direction,
  scroll_offset,
  scroll_ratio
}
```

旧客户端继续只传 `last_page` 时，服务端默认 `single + ltr`，已由隔离 API 测试证明兼容。

### 3.3 本地书库

修改前逐文件串行 `stat`，仅用文件大小判断可疑图片，损坏图片仍可能进入封面与阅读列表。修改后采用 8 路有界扫描，并按“路径 + 大小 + mtime”缓存图片头校验；损坏图片进入 `corrupted_images` 健康问题和既有 `failed_entries`，但不会阻断同目录其他正常页面。

### 3.4 数据与锁

任务、书架和阅读会话写入 SQLite 事务，不再以多份 JSON 作为活动状态。下载配额在一个调度器里原子检查全局与来源容量，避免“先占全局、再等来源”形成锁顺序死锁。

## 5. 左上角功能的可行规划

现有左侧入口继续保持兼容，后续按以下边界实现，不把业务逻辑塞回页面组件：

1. **审核**：消费统一健康问题和失败清单；支持按来源、严重级别、时间筛选；“修复”只创建现有补缺任务。
2. **基础设施**：展示 SQLite、缓存、下载令牌、来源连接和目录监听状态；数据来自只读诊断端点。
3. **来源管理**：注册表只描述能力；本地覆盖文件保存启停、并发和认证引用；Cookie/请求头不进入仓库与诊断包。
4. **备份恢复**：SQLite 一致性快照 + 本地配置清单；恢复前必须预检版本、显示差异、二次确认并自动生成回滚快照。
5. **插件中心（P2）**：基于来源 manifest、契约版本、能力声明和隔离进程，不允许插件直接写任务数据库。

## 6. 尚不在本轮强行实现的 P2

Tauri 安装包、WebDAV 冲突合并、完整插件市场、PDF 专用渲染器属于长期架构项。它们需要新的运行环境或依赖；依据用户要求，任何下载、安装或可能触发环境/服务重启的动作都必须先单独说明并取得明确同意。

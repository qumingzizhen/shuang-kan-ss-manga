# 最近在线阅读组件拆分说明

> 完成日期：2026-07-27
> 对应计划：工程化优化阶段 F（结构化拆分与冗余清理）
> 兼容约束：在线阅读会话接口、缓存维护、阅读进度和删除流程保持不变。

## 1. 原有问题

最近在线阅读面板原先内联在 `dashboard.tsx`，仪表盘需要同时维护：

- 面板筛选输入；
- 五条/十二条展开状态；
- 会话过滤和切片；
- 阅读进度、书签数量与更新时间展示；
- 继续阅读、清理缓存、复制链接、删除和刷新按钮。

其中筛选和展开属于纯展示状态，不应让仪表盘其它状态变化触发重复筛选，也不应继续扩大主组件。

## 2. 当前结构

```mermaid
flowchart LR
    D["Dashboard：会话数据与业务动作"] --> H["RemoteReaderHistory"]
    H --> F["本地筛选与展开状态"]
    H --> C["RemoteReaderHistoryCard"]
    C --> A["继续 / 缓存 / 链接 / 删除回调"]
    A --> D
```

`RemoteReaderHistory` 只接收：

- 会话摘要数组；
- 加载、阅读忙碌和维护操作状态；
- 刷新、继续、清缓存、复制链接和删除回调。

组件不直接调用 API，不操作阅读器缓存，也不修改会话数据。筛选结果由 `useMemo`
按会话数组和筛选词缓存，仪表盘中的其它输入、任务和文件库状态变化不会重复执行过滤。

## 3. 兼容行为

以下交互保持原样：

1. 默认最多显示五个会话，展开后最多显示十二个；
2. 筛选范围仍包含标题、来源名称、图库链接和 Tag；
3. 进度仍按 `last_page / page_count` 计算并限制在 0–100%；
4. 缓存清理和删除操作仍根据原维护键禁用对应按钮；
5. 最近阅读时间继续使用统一的中文相对时间格式；
6. 无匹配会话和加载状态继续复用 `AsyncState`。

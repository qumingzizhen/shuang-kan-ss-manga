# 控制台左上角功能实施规划

## 1. 当前状态

| 入口 | 当前状态 | 现有能力 | 本轮处理 |
| --- | --- | --- | --- |
| 任务控制台 | 已实现 | 多源搜索、下载、补缺、任务筛选、详情与事件日志 | 保持入口和流程不变 |
| 文件库 | 已实现 | 本地书库、阅读、导出、书架与健康检查 | 保持入口和流程不变 |
| 审核 | 尚未实现 | 仅有导航占位按钮 | 明确标记“规划中”并禁用，避免无响应假入口 |
| 基础设施 | 尚未实现 | 仅有导航占位按钮 | 明确标记“规划中”并禁用，避免无响应假入口 |

入口名称和位置继续保留。只有当对应功能完成一个可验收的纵向切片后，才启用按钮，不使用空页面或模拟数据冒充完成。

## 2. 兼容性原则

1. 不删除或改名现有 `/v1/tasks`、`/v1/library`、`/v1/reader`、`/v1/sources` 接口。
2. 新能力只增加独立路由和可选字段，不改变现有请求参数、任务流程及返回结构。
3. 开发 API 与未来 Rust API 使用相同领域契约；网页端只依赖公开 DTO，不读取内部存储文件。
4. 所有变更先提供只读能力，再增加受权限保护的写操作。
5. 审核记录、运维操作与普通任务事件分开持久化，防止单个超大日志文件继续膨胀。

## 3. 审核中心

### 3.1 目标

统一处理来源异常、下载质量问题、公开内容投诉和管理员复核，不把审核逻辑散落到任务、来源适配器或页面组件中。

### 3.2 模块边界

- `ReviewCaseService`：创建、分派、查询和关闭审核事项。
- `ReviewPolicy`：状态迁移、必填字段、重复事项合并规则。
- `ReviewRepository`：持久化审核事项和不可变决策记录。
- `ReviewConsole`：筛选列表、详情、证据摘要和处理动作。
- `AuditTrail`：记录操作者、时间、旧状态、新状态和理由，不存储来源 Cookie 或请求头。

### 3.3 增量接口

- `GET /v1/reviews`：分页、状态、类型、来源和关键词筛选。
- `GET /v1/reviews/{id}`：事项详情与决策时间线。
- `POST /v1/reviews`：由任务失败、健康检查或投诉创建事项。
- `POST /v1/reviews/{id}/decisions`：提交通过、驳回、暂缓或升级决策。

这些接口均为新增接口，不复用或改变任务输出结构。

### 3.4 数据模型

- `review_cases`：事项编号、类型、来源、关联任务/漫画、状态、优先级和时间戳。
- `review_decisions`：决策编号、事项编号、操作者、动作、理由和时间戳。
- `review_evidence`：安全化后的错误摘要、文件健康统计和引用，不直接复制完整原始响应。

### 3.5 实施顺序与验收

1. 只读事项箱：从任务失败与文件健康问题生成事项，支持筛选和详情。
2. 决策流：增加状态机、理由校验和审计记录。
3. 公开平台阶段：接入账号、RBAC、投诉与下架流程。
4. 验收要求：重复事件可合并、状态迁移可测试、每个写操作可追溯、敏感认证信息不进入审核记录。

## 4. 基础设施中心

### 4.1 目标

提供来源、API、队列、Worker、缓存、数据库和存储的统一只读运行状态；危险操作在 RBAC 完成前不开放。

### 4.2 模块边界

- `HealthCollector`：按固定周期采样各组件健康状态，避免每个浏览器页面各自轮询。
- `InfrastructureSnapshot`：形成一次不可变状态快照，网页端只渲染快照。
- `MetricsStore`：保存有限时间窗口的聚合指标，不保存逐请求明细。
- `OperationsService`：未来承载重连、暂停来源、清缓存等受权限保护的命令。

### 4.3 增量接口

- `GET /v1/infrastructure/summary`：组件状态、最近采样时间和总体告警数。
- `GET /v1/infrastructure/sources`：来源能力、最近成功/失败、延迟和限流状态。
- `GET /v1/infrastructure/workers`：队列深度、运行任务和 Worker 心跳。
- `GET /v1/infrastructure/storage`：数据库、缓存和对象存储容量摘要。
- `GET /v1/infrastructure/events`：复用一条 SSE 通道推送状态变化，不为每张卡片创建连接。

### 4.4 实施顺序与验收

1. 开发模式快照：API、来源、封面缓存和本地任务执行器的只读状态。
2. 队列/Worker 快照：NATS JetStream 和独立 Worker 接入后显示积压与心跳。
3. 存储快照：PostgreSQL、MinIO/S3 和 Meilisearch 接入后显示容量与索引健康。
4. 受控运维动作：完成账号、RBAC、二次确认和审计日志后再开放。
5. 验收要求：采样失败不拖垮主 API、浏览器断开能释放 SSE、指标有上限、所有状态含采样时间和错误原因。

## 5. 前端拆分路线

- `features/tasks`：任务表、任务详情和任务动作。
- `features/search-results`：结果分页、封面状态机、选择和批量操作。
- `features/library`：书库列表、详情和导出。
- `features/reviews`：审核事项箱和决策流。
- `features/infrastructure`：状态快照与只读指标。
- `components`：无业务状态的通用 UI；不得直接调用来源适配器。
- `lib/api`：唯一 HTTP/SSE 边界；页面组件不自行拼接服务端契约。

本轮已先迁出搜索结果无限加载、封面状态机和任务技术详情，后续按上述边界逐步拆分，不做一次性大爆炸重写。

## 6. 发布与回滚

1. 每个里程碑都必须通过现有 `scripts/check.ps1`、隐私检查和浏览器回归。
2. 新接口使用独立路由；未启用时导航保持“规划中”，不会影响现有任务和文件库。
3. 写操作必须有功能开关、权限校验和审计记录。
4. 数据迁移采用向前兼容字段和可重复执行脚本；回滚时保留数据但关闭新入口。

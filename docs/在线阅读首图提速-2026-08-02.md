# 在线阅读首图提速说明（2026-08-02）

## 背景与目标

点击「在线阅读」后，从发出请求到看到第一张图片，原先存在两段串行等待：

1. 创建会话时，源适配器要抓取画廊的全部索引页（E-Hentai 系每 40 页一页索引，
   每多抓一页还会叠加礼貌延迟，默认 2 秒），才能返回页列表；
2. 浏览器拿到会话后请求第一张图，后端再跑一次 `download-page` 抓取图片。

本次改动把第一张图出现前的关键路径压缩为「一次画廊索引请求 + 首图后台预热」，
目标是在源站响应正常时把首图等待压缩到 1 秒级别，同时**不绕过源站礼貌延迟、
不改变对外 API 契约**。

## 改动内容

全部改动在 `services/dev-api/server.mjs` 及配套配置：

### 1. 创建会话只抓首个画廊索引页

对声明了 `gallery_index_page_size` 的源（当前为 Fangliding / E-Hentai / ExHentai，
值为 20），`list-pages` 只请求画廊第一个索引页，返回前 40 页 URL；
`page_count` 仍取源站报告的完整页数。若源站未报告完整页数，会自动回退为拉取
全量页列表，保证总数正确。18comic 等一次返回全量页列表的源不受影响。

### 2. 首图后台预热

会话创建完成后，后端立即在后台预取前 N 页（默认 3，`DEV_API_READER_PREHEAT_PAGES`），
与浏览器「收到会话 → 渲染 → 请求图片」的过程并行。请求到来时命中缓存或同一个
single-flight 下载，避免再次拉起 Python 进程和网络请求。预热失败只记录日志，
不影响会话创建。

### 3. 短时间复用已有会话

同一 `source_id + gallery_url` 在 `DEV_API_READER_SESSION_REUSE_MS`（默认 24 小时）
内再次点击「在线阅读」时，直接复用已存储的页列表与阅读进度，不再重复抓取页列表。

### 4. 页列表惰性补全

当用户翻到初始 40 页之外时，`/pages` 与单页图片接口会自动拉取完整页列表并合并进
会话（受单飞保护，并发请求只触发一次）。补全发生在翻页时刻，不在首图关键路径上。

### 5. 进度与书签边界修正

会话加载、持久化时，`last_page` 与书签的校验上限改为
`max(page_count, 已知页数)`，避免部分页列表阶段误裁剪进度或书签。

## 兼容性说明

- 对外接口字段与语义不变：`pages.total` 现在基于完整 `page_count`，比此前
  只统计已知页更准确；前端已有的 `Math.max(session.page_count, pages.total)`
  逻辑天然兼容。
- `gallery_index_page_size` 是新增可选源配置字段，未配置的源行为与之前完全一致。
- 礼貌延迟、重试、单飞、缓存策略均保持不变。

## 新增配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEV_API_READER_SESSION_REUSE_MS` | `86400000` | 会话页列表复用窗口（毫秒），0 表示不复用 |
| `DEV_API_READER_PREHEAT_PAGES` | `3` | 会话创建后后台预热的前 N 页，最大 8，0 表示关闭 |

## 测试

新增 `scripts/check_reader_first_page.mjs` 回归测试，覆盖：

- 创建会话只返回首索引页（40 页图库返回 20 条、总数 40）；
- 翻页触发惰性补全并返回第 21 页；
- 单页图片接口下载成功且再次请求命中缓存；
- 短时间重复创建会话不重复抓取页列表；
- 恢复会话接口返回补全后的页列表。

# 全来源搜索链路与 Fangliding 结果解析重构

> 完成日期：2026-07-28
> 兼容范围：原搜索入口、任务入参、分页入口、下载/阅读流程和已有 JSON 字段保持不变；只增加可选元数据字段。

## 问题与根因

Fangliding 的搜索页本身包含分类、上传时间、页数和封面，但旧桥接器只保留标题、链接和 ID，并另外运行一套缩略图匹配。结果是：

- Fangliding 的 `uploaded_at` 为空，只能进入“未知时间”队列，看起来像按来源分组；
- 分类和页数被丢弃；
- 标题解析与封面解析存在两条链路，页面结构变化时容易只修好其中一条；
- 旧任务没有封面 URL 时，前端重试也无法凭空恢复封面；
- 正式 Rust 运行时仅合并来源结果，没有执行与开发 API 相同的全局时间排序。

## 统一结构

```mermaid
flowchart LR
    A["来源桥接器：搜索与抓取"] --> B["共享搜索卡片解析器"]
    B --> C["统一可选字段：封面、分类、时间、页数、评分"]
    C --> D["全局禁用词过滤"]
    D --> E["来源 + 链接去重"]
    E --> F["全部来源统一时间排序"]
    F --> G["同时间与未知时间按来源轮转"]
    G --> H["一级结果网格"]
    H --> I["本地封面代理：缓存 + 自动重试 + 手动重试"]
```

E-Hentai 和 Fangliding 都使用 `scripts/gallery_search_parser.py`。该模块一次建立结果卡片边界索引，同时支持表格行和 `div.gl1t` 缩略图网格，再从同一张卡片读取标题、封面和元数据，避免相邻漫画串图。来源桥接器只保留查询构造、请求客户端、图库详情与下载等来源差异。

新增来源仍只需要：

1. 在 `config/source-adapters.json` 注册描述和能力；
2. 实现标准桥接命令；
3. 复用通用 HTTP、卡片解析、过滤、去重、排序、封面代理和 UI；
4. 为来源特有 HTML/API 响应增加离线样例。

API、任务运行时和网页不按来源 ID 写条件分支。

## 数据契约

`TaskSearchResult` 继续保留原字段，并支持以下可选字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `thumbnail_url` | `string \| null` | 只接受来源允许主机；由本地代理下载和校验 |
| `uploader` | `string \| null` | 来源没有提供时为空 |
| `uploaded_at` | `string \| null` | 开发 API 规范化为 ISO 时间 |
| `category` | `string \| null` | 如 `Doujinshi`、`Manga`、`Game CG` |
| `page_count` | `number \| null` | 1 至 10000 的整数 |
| `rating` | `number \| null` | 来源明确提供的 0 至 5 数字；不根据 CSS 图片位置猜测 |

Rust 领域模型、Rust 来源适配器、Rust 任务运行时、Node.js 开发 API 和 TypeScript 前端使用同一组可选字段。旧任务 JSON 缺少新字段时仍能正常反序列化。

## 全局排序

搜索每一页先并发请求所有选中来源，随后只在合并集合上执行一次过滤、去重和默认排序：

1. 有合法时间的结果按时间由近到远；
2. 时间完全相同的结果按来源轮转，避免来源批次占满首屏；
3. 无法解析时间的结果排在已知时间之后，并按来源轮转；
4. 下滑取得下一页后，与已有结果合并去重，再对完整集合重新排序。

主排序复杂度为 $O(n\log n)$，来源轮转为 $O(n)$，额外空间为 $O(n)$。Rust 实现移动结果所有权，不复制标题、URL 或 Tag。

## 封面加载

封面链路分为两层：

- 服务端代理对远端请求执行超时、重试、可信主机、DNS、大小、图片签名和原子缓存校验；相同封面并发请求合并为一次；
- 浏览器端第一次失败后延迟重试，不会立即判定永久失败；自动重试耗尽后显示“点击重试”，用户可重新触发带新请求参数的加载。

历史任务若从未保存 `thumbnail_url`，必须重新运行搜索才能获得封面地址；这类任务不是图片下载失败，而是旧结果数据本身缺字段。

## 验证范围

- 离线卡片样例验证表格和缩略图网格、懒加载图片、相邻卡片隔离、分类、时间、页数和明确评分；
- 真实 Fangliding 公共搜索页抽样结果的封面、时间、分类和页数字段覆盖率均为 100%；
- Node.js 测试验证三来源全局排序、相同时间轮转、过滤、去重和可选数值校验；
- Rust 测试验证正式运行时的多来源时间排序和桥接日期格式；
- 前端测试验证默认混排、一级元数据、封面延迟重试及最终失败后的再次加载；
- 完整项目检查、生产构建、浏览器回归和公开仓库隐私检查作为提交门禁。

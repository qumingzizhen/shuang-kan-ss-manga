# 文档优化执行矩阵（2026-07-28）

本文把《新建 DOCX 文档 (2).docx》的 121 条建议转换为可验证的工程任务。执行顺序严格遵循 P0 → P1 → P2；每项只有在代码、自动化测试和文档三者齐备后才标记完成。

## P0：数据正确性与可恢复性

| 工作包 | 当前差距 | 实施方案 | 验收门槛 |
| --- | --- | --- | --- |
| 跨语言契约 | Rust、Node、Python 各自维护对象形状 | Rust 领域模型生成受版本控制的 JSON Schema；三运行时使用同一组契约样例做规范化和字节级比较 | 契约检查加入 `check.ps1`，任一差异返回非零 |
| 下载并发 | 只有适配器内的有界线程池，缺少全局与分源配额 | 在任务调度层增加全局令牌桶和来源令牌桶；适配器仅执行获准任务 | 并发峰值不超配额，无死锁，取消后令牌归还 |
| 事务持久化 | 任务、阅读进度、书架使用三个 JSON 文件 | 使用 Node 内置 SQLite、WAL、事务和索引；首次启动自动导入旧 JSON，旧文件不删除 | 迁移零丢失；异常中断后数据库完整；接口结构不变 |
| 中断恢复 | 重启后未完成任务被直接标记失败 | queued/running/paused 恢复到队列；下载复用已完成文件和 `.part` 状态 | 模拟重启后任务继续，已完成页面不重复下载 |

## P1：核心链路

| 工作包 | 实施内容 | 主要验证 |
| --- | --- | --- |
| 搜索 | 来源时间统一为 UTC；全源混排；游标/分源页码回填；筛除后自动补足；URL 规范化和软去重；逐来源状态、错误、超时和单源重试 | 全失败、部分失败、重复、跨时区、筛选不足、单源重试 |
| 阅读器 | 连续模式记录像素与比例，单双页记录页码；切换确认；可取消图片队列；LTR/RTL 双页；横图单页、竖图成对；键盘、触摸、夜间与长条模式 | 快速翻页无重复请求；模式切换不丢进度；移动端触摸 |
| 本地书库 | 自然排序；CBZ/ZIP/PDF/文件夹损坏容错；失败清单；目录监听；健康修复 | 特殊文件名、空目录、损坏包不崩溃且可定位 |
| 下载体验 | 速度、ETA、单页失败与重试；安全命名；图片大小、尺寸、格式完整性联合校验；通知 | 异常图片重试有上限；Windows 名称均合法 |
| 配置与诊断 | 来源启停、Cookie/请求头、并发、连接测试；备份恢复；中文错误；一键诊断包；敏感字段脱敏 | 配置往返一致；诊断包不含 Cookie/token |

## 工程治理与质量门

- 单元测试覆盖来源解析、搜索、下载、本地书库的正常、异常和边界场景。
- 契约测试固定为 P0 提交门。
- E2E 覆盖搜索 → 详情 → 阅读/下载 → 书库完整路径，并补网络故障、磁盘不足、来源异常和进程中断。
- CI 增加格式、Rust/Node/Python 测试、依赖安全扫描和敏感信息检查。
- 性能基线覆盖 1000 条搜索结果、10 个并发下载、大书库扫描和长时间阅读；回退超过 15% 阻断发布。
- 依赖保持锁定；Python 后续补充哈希锁文件。新增依赖或安装工具前必须先取得用户许可。

## P2：长期演进

- 来源插件 SDK：统一 manifest、能力声明、输入输出契约、生命周期和隔离策略。
- Tauri/一键安装包：取消盘符映射和中文路径规避脚本，启动过程可视化。
- WebDAV 同步：收藏、进度和配置的冲突合并、加密与离线队列。
- 可插拔阅读器：渲染模式与控制器解耦，支持后续 PDF/条漫/双页扩展。

## 兼容性约束

本轮不改变已有 HTTP 路径、请求字段、任务业务流程和返回 JSON 结构；旧 JSON 只作为一次性迁移输入且保留；不引入无关第三方依赖；所有改动适配现有 Windows、Node、Python 和 Rust 环境。
